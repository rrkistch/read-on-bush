# 微信读书原生接入设计

日期：2026-10-26

状态：实现及请求链路修正已完成，登录态超时由用户复验；已完成的验证与剩余检查见[实施记录](../plans/2026-10-26-weread-implementation.md)。

## 目标与第一版范围

在 Read On Bush 内登录微信读书、浏览个人书架并阅读有权访问的正文，沿用现有伪装终端、阅读面板、隐私模式和快捷键习惯。

用户已确认以下范围：扫码登录及手动 Cookie、微信书架同步、章节目录与按章阅读、本地断点续读、云端进度读取与可关闭的回传。划线笔记、热门想法、富排版阅读器不在第一版内。

第一版以文字阅读为主。正文中的图片保留占位提示，不下载全书、不提供导出；不承诺扫描版 PDF、漫画或纯图片章节可读。遇到受限、付费或不支持的内容，说明原因并允许用户打开官方阅读页面，不将错误当作空章节跳过。

## 选择原生书源，不移植整套界面

考虑过三条路径：

1. **原生书源适配，采用。** 在线服务负责认证和取数，独立阅读控制器连接现有显示层。最符合本项目的伪装阅读定位，也不引入 React/Vite 子应用。
2. 独立 Webview 阅读器。便于富排版和批注，但会形成两套阅读、隐私和快捷键行为，维护成本更高。
3. 仅打开或嵌入官方网页。可以作为错误时的跳转入口，不能完成项目内伪装阅读和统一进度管理。

touchFish 只作为功能及协议行为研究参考。其 LICENSE.txt 是专有许可，实施时不复制或改写其源文件，也不引入其代码作为依赖。本项目独立编写适配层和测试，并在说明中记录参考来源。

## 用户操作

- 书架工具栏新增“微信读书”入口，打开原生 Quick Pick，提供登录、设置 Cookie、刷新书架、进度回传设置及退出登录。
- 扫码登录使用专用小型 Webview 显示二维码和等待、待验证码、成功、过期或失败状态；验证码通过 VS Code 输入框提交。取消或关闭登录窗口立即结束轮询。
- 手动 Cookie 使用密码输入框；不要求用户把 Cookie 发到聊天或写入 settings.json。
- 登录成功自动拉取书架。书籍显示云来源标识，点击后在当前选择的伪装终端或阅读面板中阅读；展开书籍获取目录，点击章节跳转。
- 复用下一页、上一页、`j` 选章、`a` 自动翻页、`d` 伪装、`q` 隐蔽及退出的现有行为。在线书籍不占用 TXT 的状态栏阅读或编辑器翻页快捷键。
- 进度回传默认关闭。启用时说明会更新微信读书的云端位置；关闭时停止后续回传并撤销尚未发送的任务。

## 模块边界

保留现有分层，新增以下职责，不做无关重构：

- `infrastructure/weread/`：HTTPS 传输、响应校验、Cookie 会话、扫码协议、书架、目录、正文与云端进度 API。网络客户端可注入，便于使用固定响应测试。
- `application/WeReadService.ts`：拥有当前账号和登录状态，编排登录、退出和书架刷新；控制账号切换后的异步结果与缓存清理。
- `formats/weread/`：`WeReadProvider` 提供书籍路由、目录及 Reader；`WeReadReader` 拥有阅读生命周期、异步章节切换、自动翻页和回传队列。
- `domain/books/`：微信读书的位置及章节模型，复用现有 `wrapChapter` 等纯分页工具，不依赖网络或 VS Code。
- `presentation/`：登录窗口及少量书架来源显示；正文继续使用 `PaginatedReaderDisplay` 与 `SurfaceRouter`。

`ApplicationContext` 组装这些模块；`ReadingSession` 继续是当前 Reader 的唯一所有者。在线 Reader 不直接继承要求“全书已加载”和同步跨章翻页的 `PaginatedReaderBase`，避免把网络 I/O 塞进本地格式模型。

### 书籍身份及兼容

- `BookData` 新增可选的微信来源信息，包含账号 ID 和远端 bookId；缺省仍表示既有本地书籍。
- 在线书籍使用独立 `format: 'weread'`、带来源和账号的稳定本地 ID，以及 `weread://` 资源地址。远端原始格式作为来源元数据保存，不冒充本地 EPUB 文件。
- 新增 `wereadProgress`，保存稳定 chapterUid、目录索引、本地章内字符偏移、更新时间及待回传状态；不复用 `epubProgress` 或 TXT 的片段索引。
- Registry 增加在线格式路由；本地导入仍按扩展名路由，原有 `getSupportedExtensions`、导入对话框与已有调用方式保持不变。
- BookCatalog 对明确的微信来源走账号与服务可用性检查，本地书籍仍执行原有文件存在检查。不能对在线 URI 调用 `fs.existsSync` 或按路径目录分组。
- 书架在原有最近阅读及本地书籍展示之外增加固定的微信书籍分组；本地分类、目录分组和排序行为保留。微信书籍按当前账号过滤，正常模式显示来源，隐私模式使用中性分组名和不含账号信息的书籍别名。
- 微信书籍的右键操作不提供本地重命名、路径分类或删除云端书架的暗示；保留隐私别名和移出最近阅读。第一版不修改远端书架内容。

## 登录与账号隔离

- 长期 Cookie 只写入 `ExtensionContext.secrets`。临时扫码 Cookie、验证码、readerToken 仅驻留内存，不进入日志、globalState、异常原文或 Webview 消息。
- Webview 只接收二维码内容与显示状态；扩展宿主执行认证请求。二维码由本地依赖生成，不将登录链接发送给第三方二维码服务。
- 网络请求限于微信读书所需的 HTTPS 域名；拒绝携带 Cookie 跳转到其他域名。认证失败最多合并续期一次并重试一次，失败后提示重新登录，不无限重试。
- 有刷新令牌时主动后台检查续期：恢复登录、登录成功及阅读入口检查，并每 30 分钟检查一次，成功后 6 小时内不重复；无刷新令牌的手动 Cookie 保留既有用法。后台失败记入脱敏日志，不阻断仍然有效的请求。
- 普通请求设置超时；扫码长轮询单独设定等待上限。取消、退出、切换账号和扩展卸载时取消请求并清理定时器。
- 登录会话使用递增版本标识。旧扫码、旧续期和旧书架请求的迟到结果不能覆盖新账号或已退出状态。
- 账号变更前停止旧账号 Reader，保留已保存的本地阅读位置。内存正文缓存清空，旧账号条目和最近阅读不在新账号下出现，回传任务不能跨账号执行。
- 退出登录删除持久凭据、清除内存会话并关闭微信 Reader；本地 TXT/EPUB/PDF 仍可使用。旧账号的本地阅读位置仅用于该账号再次登录后的续读。

## 书架和章节数据流

### 书架刷新

成功响应经校验、去重后按“账号 + bookId”合并。只更新书名、作者和远端元数据，保留本地隐私别名及进度；不触碰本地书籍。完整刷新成功后不再返回的云端书籍从当前云分组隐藏，但保留该账号的本地续读记录。请求失败不清空已有书架；有效的空书架显示空状态。

目录保留真实 chapterUid 与显示顺序，不假定 UID 连续，也不把 UI 索引当作 API 参数。章节标题和当前目录高亮遵循现有隐私设置。

### 阅读与按章加载

打开书籍检查账号后，并发准备目录、阅读会话和云进度，完成位置选择后请求当前章节。显示可取消的分阶段加载状态。正文适配器独立处理远端响应并转换成纯文本与图片占位；不执行远端 HTML、脚本或样式。转义和控制字符清理沿用项目显示安全要求。

#### 请求链路取舍

- 采用独立元数据并发，而非串行累积等待；云进度失败仍走既有的明确选择／暂停回传流程，必要元数据失败则取消其他未完成请求。
- 采用阅读页格式元数据和正文首分片的明确类型，而非逐章查询书籍详情。格式未知时，首片若为匹配 bookId／chapterUid 的章节元数据，使用 TXT 分片；若为校验通过的编码分片，使用 EPUB 分片并复用已取得的首片。未知响应不猜测格式。未知 TXT 格式首次需要探测，识别后在当前阅读会话内复用。
- 保留真实阅读页会话参数，不使用参考实现中的固定 ps／pc 值。保留有界超时，不采用 GET 的无限等待；单个正文分片失败时取消同组其他分片。

Reader 只缓存当前及相邻章节，最多保留三章的内存 LRU，不写入正文磁盘缓存。当前章加载成功后最多预取下一章；预取不改变位置、不上报进度，也不为错误弹出反复提示。全局“清除缓存”同时清理该内存缓存，不改变原有 EPUB/PDF 共享缓存语义。

章内用字符锚点分页，不因宽度或行数设置改变存储位置。跨章翻页在控制器中等待目标章节成功后一次性切换，上一章末页不足一屏时不强制拼接下一章；不会跳过未加载或无权读取的章节。加载失败保留原来的正文与位置，可重试。请求中的重复翻页不会重复跨章，新的显式跳转可取代旧跳转。

关闭书籍、切换账号或打开另一书后，迟到响应不得渲染、写进度或回传。失焦隐蔽和隐私模式切换不改变当前位置；未完成的响应不能把已隐蔽的正文重新暴露。

第一版在线书籍不启用全书搜索，也不在打开时遍历下载全书；`f` 给出当前内容暂不支持全文搜索的现有提示。本地全文搜索保持原样。

## 进度：本地精确，云端第一版按章

### 位置粒度

本地保存 chapterUid 和当前章纯文本的字符偏移，重启及改变显示尺寸后均能恢复章内位置。目录更新以 UID 重新定位，不能把旧索引直接用于不同章节。

云端第一版采用**章节级同步**：读取云端 chapterUid，跨设备续读定位至对应章节开头；回传写入真实 chapterUid，章内偏移为章节起点，不使用清洗后文本偏移冒充微信读书协议偏移。该粒度在设置说明及 README 中明确。本地章内断点不会因此退化。

### 起始位置和冲突

- 没有本地位置时，采用有效的云端章节；无云端位置时从第一章开始。
- 本地和云端在同一章时，保留本地精确位置。
- 两端章节不同时，在打开时让用户选择“本地位置”或“微信读书位置”，并显示章节信息；隐私模式仅显示章节序号。取消选择就取消打开，不覆盖任一进度。
- 云进度查询失败但存在有效本地位置时，显示“云进度暂不可用，继续本地位置”的明确提示后续读；没有本地位置时提供从第一章开始或取消的选择。
- 本地或云端 UID 已不在目录时，提示该位置失效并让用户选章，不静默映射到另一章。

### 回传时机与可靠性

只有用户启用回传且实际阅读位置发生变化才产生任务。打开目录、加载正文、预取、隐蔽和恢复显示本身不产生上报；不以固定假读时长或随机历史时间构造阅读记录。

回传串行、合并同书的最新章节，正常阅读时最多每 30 秒提交一次。回传使用真实会话时间；若协议需要阅读时长，只计算实际显示正文的时段，失焦或隐蔽不计时。云端章节同步不宣称为微信读书阅读时长或排行榜记账功能。

本地位置先保存，再尝试网络提交。停止阅读或切书时立即保存本地位置，对未提交的章节执行一次有界回传；网络失败不妨碍退出或打开本地书。失败保留该账号的待回传章节并给出可重试状态。下次打开时先比较云端位置，经起始位置选择后再合并任务，不能把旧离线任务直接覆盖手机上更新的位置。

关闭回传开关时清空未发送任务并取消可取消的请求；已被服务器接受的提交无法撤销，界面不声称能回滚。退出和切换账号后，不再提交旧账号任务。

## 错误和恢复

- 未登录、登录过期、网络超时、服务限流、正文权限不足、格式不支持分别转换为明确的中文提示；敏感原始响应不直接透出。
- 会员或购买限制按账号实际权限处理，不尝试绕过。打开官网只在用户点击后发生。
- 重试保留当前状态，不能将失败响应解析为空书架或空正文。后台失败不连续弹窗，用户主动操作时说明下一步。
- 认证和正文协议分别隔离。正文协议测试未通过时，不将“登录和书架可用”标记为微信阅读功能已完成。

## 验收证据

实施时先建立固定响应及可控网络测试，再通过真实账号确认关键路径；真实 Cookie 不进入测试文件。

1. 认证：扫码等待、验证码、过期、取消、成功；手动 Cookie；并发续期去重；换账号及退出后迟到响应无效；持久凭据仅使用 SecretStorage。
2. 书架：重复刷新无重复书籍；有效空响应与失败区分；本地书不受影响；跨账号隔离；目录使用真实 UID；最近阅读及隐私模式不泄漏书名或账号。
3. 阅读：TXT 类正文与 EPUB 类正文的已授权样例能正确转换；首章、章内前后翻页、跨章、目录跳转、调整行宽、停止后续读；失败及快速切书不覆盖当前画面或位置。
4. 进度：本地章内恢复；云端章节恢复；不同章节的选择；回传默认关闭、开关生效、真实章节参数、节流与最终保存；网络失败及离线任务恢复不覆盖新云位置。
5. 交互实测：在 VS Code Extension Development Host 中检查扫码窗口及书架实际显示，分别使用伪装终端和阅读面板验证阅读、隐蔽、自动翻页、失焦以及切换本地书。
6. 回归：运行类型检查、lint 及现有 VS Code 测试，重点覆盖本地格式路由、TXT 快捷键、EPUB/PDF 翻页、全文搜索、缓存和隐私行为。

真实登录及正文权限由用户在运行中的扩展界面确认。若环境无法运行 VS Code 测试或尚无真实账号联调，交付时逐项标明缺少的证据与影响，不能用 mock 测试替代实际可读性结论。
